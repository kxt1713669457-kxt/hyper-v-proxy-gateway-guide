# Hyper-V 虚拟机与独立代理网关配置

按顺序完成：**准备 VPS 和节点 → 安装 Windows 虚拟机 → 部署独立网关 → 检查出口和断网保护**。

```text
Windows 虚拟机 → Hyper-V 私有交换机 → Debian 网关 → VPS 节点 → 互联网
```

## 一、准备 VPS 和 Clash Nyanpasu

如果需要使用私有“纯净节点”，先准备私有服务器，配置好 VPS 上的代理服务，再进行下面的步骤。私有服务器不保证 IP 一定纯净或被目标服务接受。

1. 在 VPS 部署代理服务，保存协议、服务器地址、端口和认证信息。
2. 在宿主机安装 Clash Nyanpasu，导入兼容的节点 YAML 或订阅。
3. 在「代理」页面选择节点，测试延迟和网页连接。
4. 需要 TUN 时，在 Nyanpasu 中开启 TUN 并测试；如果一开就断网，先关闭 TUN，按下文「常见问题 1」排查。
5. 准备节点配置文件供网关部署使用。**不要把密码、订阅链接、私钥上传 GitHub。**

> 独立网关使用部署时的节点配置快照。宿主机切换节点后，网关不会自动同步；需要更新网关配置并重新测试。

---

## 二、启用 Hyper-V

1. 确认 Windows 为支持 Hyper-V 的版本，BIOS/UEFI 已开启硬件虚拟化。
2. 按 `Win + R`，输入 `optionalfeatures` 并回车。
3. 勾选 **Hyper-V** 下的管理工具和平台，点击「确定」。
4. 按提示重启电脑，在开始菜单打开 **Hyper-V 管理器**。

---

## 三、创建 Windows 虚拟机

1. 从微软获取 Windows ISO，保存到空间充足的磁盘。使用介质创建工具时选择「为另一台电脑创建安装介质 → ISO 文件」。
2. 打开 Hyper-V 管理器，点击右侧「新建 → 虚拟机」。
3. 填写名称和存储位置；选择与 ISO 兼容的虚拟机代数。
4. 设置内存、处理器和动态虚拟硬盘。本机历史配置曾使用 **2 核、6 GB 内存、最大 64 GB 动态磁盘**，按实际可用资源调整。
5. 安装阶段选择 `Default Switch`，挂载 ISO，完成向导。
6. 右键虚拟机「连接 → 启动」，按提示完成 Windows 安装。
7. 在虚拟机内打开 PowerShell，运行 `whoami`，记下实际用户名；后续输入的是 Windows 账户密码，不是 PIN。

---

## 四、部署独立代理网关

### 1. 准备信息

- Windows 虚拟机名称及其当前交换机。
- 节点配置文件的本地路径，以及节点协议。
- 管理员权限；虚拟机账户密码由本人在凭据窗口输入。
- 记录虚拟机原网卡、IP、DNS 和路由，以便恢复。

### 2. 按部署提示词创建网关

1. 打开 [Hyper-V 独立代理网关部署提示词](https://github.com/0xVoidw/hyper-v-proxy-gateway-deployment-prompt)，按项目说明交给具有管理员权限的工具执行；检查工具提出的改动后再执行。
2. 指定目标 Windows 虚拟机及节点配置文件，不要把节点密码贴进公开文档。
3. 创建 Hyper-V **私有交换机**和 Debian 网关虚拟机。网关使用两张网卡：一张连接上游网络，一张连接私有交换机。
4. 在网关配置代理、DHCP/DNS 和防火墙，确保代理故障时阻断直连。历史环境使用 Mihomo、dnsmasq、nftables；具体规则需要按接口和节点配置生成。
5. **先检查网关管理连接和代理服务**。历史首次部署时，开启代理导致网关管理连接异常；修复并确认网关稳定前，不要切换 Windows 虚拟机。
6. 网关就绪后，把 Windows 虚拟机网卡接入私有交换机。不要再给该虚拟机添加 Default Switch 等可直连公网的网卡。

历史环境的私有网络网关为 `10.249.0.1/24`，来宾通过 DHCP 获取地址和 DNS；其他环境应避免与现有网段冲突。

### 3. 节点变更时

1. 在网关安全更新节点地址、端口或认证信息。
2. 按新节点调整所需防火墙规则，检查代理服务状态。
3. 重新执行下一节所有测试。宿主机更换节点不会自动更新网关。

---

## 五、检查网络是否正确

在 **Windows 虚拟机内部**依次执行：

1. 打开 PowerShell，运行 `ipconfig /all`，检查默认网关和 DNS 是否指向预期的私有网关。
2. 打开网页检查公网 IP，确认显示的是预期节点出口。
3. 测试网页访问、DNS 解析和 WebRTC/UDP；同时检查 IPv6 是否按网关设计阻断或转发。
4. 停止网关中的代理，再尝试访问网页和直接连接公网 IP；**应当断网，不能回退到直连**。
5. 恢复代理，再次检查 IP、网页、DNS 和 UDP；关闭网关也应断网。
6. 重启网关后重复测试。每次更换节点、修改网卡或防火墙后重新测试。

历史测试中，HTTPS、DNS、UDP/STUN、IPv6 阻断及代理停止后的公网 TCP 阻断有通过记录；Edge 的部分 STUN 请求出现 `701`，真实会议和所有浏览器配置未完全测试。测试通过仅覆盖当时测试的路径。

## 六、日常使用

### 开机

1. 启动网关虚拟机，等待代理、DHCP 和防火墙就绪。
2. 启动 Windows 虚拟机。
3. 检查公网 IP，再开始使用。

### 关机

1. 保存并正常关闭 Windows 虚拟机。
2. 确认其已关闭，再正常关闭网关。
3. 最后关闭 Hyper-V 管理器窗口。

历史制作过一键启动和关闭脚本；使用前检查启动器指向的文件、PowerShell 脚本和网关密钥均存在。自测和模拟通过不代表真实开关机已验证。

### 恢复原网络

需要退出独立网关时，使用部署时备份或恢复脚本，将虚拟机网卡接回原交换机。**接回 Default Switch 后，独立网关的断网保护不再适用。**

## 七、常见问题

### 1. Clash 一开 TUN 就断网，出现 `reject loopback connection`

历史原因：WLAN 的 IPv4 转发开启，出站流量被 TUN 再次捕获。按以下步骤排查：

1. 关闭 TUN，恢复网络。
2. 打开 PowerShell，查询当前网卡及转发状态：

   ```powershell
   Get-NetIPInterface -AddressFamily IPv4 | Format-Table InterfaceAlias,Forwarding
   ```

3. 如果实际联网网卡为 `WLAN`、转发为 `Enabled`，并确认不需要用它共享网络，以管理员身份运行：

   ```powershell
   Set-NetIPInterface -InterfaceAlias "WLAN" -AddressFamily IPv4 -Forwarding Disabled
   ```

4. 回到 Nyanpasu 开启 TUN，重新测试节点与网页。如果原设置是 `Enabled`，以后需要恢复共享时将 `Disabled` 改为 `Enabled`。
5. 修改 YAML 后，在「设置 → 内核管理」重启内核，并检查运行配置。历史尝试指定 `interface-name: WLAN` 和切换 Mixed 堆栈均未单独解决问题；固定 WLAN 出口还可能影响有线网络。

### 2. 虚拟机显示“严重错误—已暂停”

1. 检查虚拟机所在磁盘剩余空间。历史案例是 E 盘耗尽，检查点合并失败。
2. 不要反复点击继续或重启；先扩容、释放足够空间，或通过 Hyper-V 的迁移功能迁到空间充足的磁盘。
3. 核对磁盘链后再恢复。不要手动删除正在使用的 `.vhdx`、`.avhdx` 或 `.vmrs` 文件。

### 3. 增强会话没有登录框或凭据无效

1. 在虚拟机连接窗口取消「查看 → 增强会话」，先用基础会话登录。
2. 在虚拟机中运行 `whoami`，确认真实用户名；登录时使用账户密码，不是 PIN。
3. 在虚拟机「设置 → 账户 → 登录选项」检查 Windows Hello 限制，按 [微软增强会话说明](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/enhanced-session-mode) 排查。
4. 历史记录中开关显示与注册表值不一致，修改注册表没有证明修复；不要反复运行同一修复脚本。

### 4. 一键启动提示找不到文件

1. 右键启动器查看目标路径，确认 `.cmd` 和对应 `.ps1` 文件确实存在。
2. 检查脚本依赖的网关密钥和原项目文件是否还在。
3. 修正路径后先执行脚本自测，再保存工作并实际验证；历史问题是入口指向桌面，但原文件只放在项目输出目录。

### 5. 虚拟机窗口无法随意缩放

基础会话的缩放是缩放画面；需要动态调整分辨率时尝试增强会话。遇到登录问题先按上一节排查。
